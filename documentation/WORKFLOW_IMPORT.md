# ComfyUI Workflow Import & Model Library

> Feature added in v0.6.0 (frontend + backend).

## 1. Import a ComfyUI workflow from a `.md` file

The **My Models** page now has an **Import workflow** button. The flow has three steps:

1. **Upload** — drag the `.md` file (or paste the Markdown content).
2. **Review** — Centraliza.ai lists every model found, its size, source repository and destination folder in ComfyUI. You can uncheck optional models, change the destination folder of any file, or paste a direct URL for a file that could not be resolved.
3. **Download** — files are downloaded from Hugging Face into `ComfyUI/models/<folder>` with progress, speed, cancellation and resume support.

### Supported Markdown format

This is the **Model Links** block generated by official ComfyUI templates:

```markdown
### Model Links

- Hugging Face:Comfy-Org/gemma-4
- ModelScope:Comfy-Org/gemma-4

### Input Asset

- `input.png` — required workflow input ( `input/input.png` )

### text_encoders

- `gemma4_e2b_it_int8_convrot.safetensors` (4.84 GB) — optional, only needed when `prompt_enhance` is enabled.
- `gemma4-12b-with-proj_ltx-2.5-comfy-int8-convrot.safetensors`

### diffusion_models

- `ltx-2.5-22b-distilled-transformer-comfy-int8-convrot.safetensors`

### vae

- `ltx-2.5-video-vae-bf16.safetensors`
- `ltx-2.5-audio-vae-bf16.safetensors`

### latent_upscale_models

- `ltx-2.5-latent-spatial-upscaler-x2-bf16-1.0.safetensors`
```

Parsing rules:

- **Headings** (`###`, `**text**` or a standalone line) define the destination folder:
  `text_encoders`, `diffusion_models`, `vae`, `loras`, `checkpoints`,
  `controlnet`, `upscale_models`, `latent_upscale_models`, `embeddings`,
  `clip_vision`, `style_models`, `ipadapter`, `audio_encoders`,
  `animatediff_models`, `model_patches`, `LLM`, and more.
- **Backticked names** (or names in a list/table) are the files to download.
- `(4.84 GB)` is used as a size estimate until the real size is known.
- The word `optional` marks a model as optional and it is **not** selected by default.
- The **Model Storage Location** folder tree is ignored.
- **Input Asset** entries generate a warning: workflow inputs are not models and belong in `ComfyUI/input`.

The parser also accepts:

- Direct file links:
  `https://huggingface.co/org/repo/resolve/main/models/vae/file.safetensors`
- Markdown tables with model, link and folder columns.
- Lists in the form `Name — https://...`.
- Repository URLs (`https://huggingface.co/org/repo`) as long as filenames appear
  elsewhere in the document.
- ModelScope repositories (tried as a Hugging Face mirror).

### Automatic repository discovery

ComfyUI templates do not always list every repository. After checking the
document repositories, Centraliza.ai searches Hugging Face for public
repositories that contain the exact filename. Matches are shown with an
**AUTO** badge in the review step so the user can confirm before downloading.

### Destination folder

`ComfyUI/models` is detected automatically from:

1. `comfyModelsDir` (explicit preference in `config.json`);
2. `comfyDir` (`<comfyDir>/models` or `<comfyDir>/ComfyUI/models`);
3. scan folders (`scanDirectories`) that contain `ComfyUI/models` with at least
   two common model folders (`checkpoints`, `vae`, `loras`, ...).

If no folder is found, the review step lets you choose one manually. The choice
is stored in `config.json` (`comfyModelsDir`).

### Token, concurrency and safety

In the importer's **Advanced settings**:

- **Hugging Face token** — required for gated or private repositories. Stored
  locally in `config.json` (`hfToken`).
- **Simultaneous downloads** — 1 to 4 (default: 2).

Filenames are sanitized and the final path is validated so it can never leave
the ComfyUI models folder (path traversal protection).

### Files and history

- History: `data/workflow-jobs.json` (last 30 jobs; ignored by Git).
- Active state: process memory; after a restart, interrupted jobs are marked as
  `interrupted` and can be retried from the import history.
- Partial downloads use `<file>.part` and resume with HTTP `Range`.

## 2. Per-section organization in **My Models**

Each section (Standalone, LM Studio / Hugging Face, Ollama, ComfyUI) now has its
own organization bar:

- **Sort by**: date added, size, name, function or format.
- **Direction**: ascending/descending.
- **Filter by function**: LLM/Chat, Coding, Reasoning, Vision, Embedding,
  Image, Video, Audio, Upscaler, LoRA, VAE, ControlNet, Text encoder,
  Diffusion model, CLIP Vision, Style model, IP-Adapter.
- Preferences are stored per section in `config.json` (`modelViewPrefs`).

Functional classification comes from the backend (`backend/catalog.js`), based
on the ComfyUI folder and the filename. Each card also shows the date added,
quantization (`Q4_K_M`, `bf16`, ...) and parameter count (`9B`, `27B`).

## 3. API

| Method | Route | Description |
| --- | --- | --- |
| `GET` | `/api/workflows/config` | Detected folder, candidates, configured token and concurrency. |
| `POST` | `/api/workflows/config` | Saves `comfyModelsDir`, `hfToken`, `workflowConcurrency` and `workflowAutoDiscover`. |
| `GET` | `/api/workflows/template` | Downloads an example `.md` file. |
| `POST` | `/api/workflows/inspect` | `{ markdown, fileName?, token? }` → plan with entries, repositories, destinations and warnings. |
| `POST` | `/api/workflows/start` | `{ jobId, entries:[{id,selected,category,url?}], token? }` → starts the queue. |
| `GET` | `/api/workflows` | History + configuration. |
| `GET` | `/api/workflows/:id` | Job state. |
| `POST` | `/api/workflows/:id/cancel` | Cancels the job (keeps `.part` files for resume). |
| `POST` | `/api/workflows/:id/retry` | Retries failed/cancelled entries. |

Socket.io events:

- `workflow-progress` — `{ jobId, entryId, status, progress, downloadedBytes, totalBytes, speed, error }`
- `workflow-complete` — `{ jobId, status, summary }`
- `models-updated` — emitted at the end to refresh the model list.
